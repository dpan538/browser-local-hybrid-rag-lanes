## Repository Context

The research repo is:

`browser-local-hybrid-rag-lanes`

This is an independent reproducible research repository. It is not an archive
product iteration. It should not depend on private runtime state, browser
cache, model weights, image assets, or product-specific archive logic.

The core research question is:

**What should not be generated by a local small model in browser-local RAG?**

The current thesis is:

Browser-local small-model RAG exposes a **generation allocation** problem.
Because browser-local models are small, latency-sensitive, and often deployed
over private or rights-aware archive evidence, the system should not treat the
local model as the universal answer surface. Some answer lanes should be
handled by deterministic UI/runtime logic, while other answer lanes still need
bounded generation.

The proposed execution modes are:

- deterministic evidence-field rendering;
- deterministic insufficient-evidence refusal;
- bounded browser-local generation;
- compound deterministic-plus-generative answers.

The strongest phrasing so far is:

**Hybrid answer lanes separate deterministic evidence delivery from generative
research guidance in browser-local small-model RAG.**

## Required Search Areas

### 1. Browser-Local LLM Inference

Questions:

### 2. Browser-Local Retrieval And Private RAG

Key distinction to test:

### 3. RAG Grounding, Attribution, Citation Faithfulness, And Provenance

Questions:

- How does the RAG literature evaluate grounding and citation faithfulness?
- What is already covered by attribution-to-source, cited answer evaluation,

Key distinction to test:

### 4. RAG Abstention, Refusal, And Evidence Sufficiency

Key distinction to test:
