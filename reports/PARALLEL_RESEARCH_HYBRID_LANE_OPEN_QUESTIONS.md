# Parallel Research Hybrid Lane Open Questions

Generated: 2026-06-08

Scope: open questions for the independent hybrid answer-lane literature and
methodology branch. These questions are not blockers for the main Round 03
experiment.

## Core Research Questions

1. What should not be generated by a browser-local small model?

   Candidate answer: exact source/rights fields, image-state caveats,
   public-domain/reuse status, and mandatory insufficient-evidence refusals.

2. Which answer lanes need generative synthesis?

   Candidate answer: comparison, more-context requests, region/period
   recommendations, current-object explanation, and research-navigation help.

3. Can hybrid answer lanes be evaluated as a RAG method rather than a product
   implementation detail?

   Candidate answer: yes, if the method defines a lane taxonomy, an execution
   routing policy, contract metrics, usability metrics, and separate latency
   accounting for model generation and hybrid system output.

## Method Questions

1. What is the minimal lane taxonomy?

   Current candidate:

   - deterministic evidence-field delivery;
   - deterministic refusal;
   - generative explanation;
   - generative comparison/recommendation;
   - mixed deterministic prefill plus bounded generation.

2. What fields are contract-bearing?

   Current candidate:

   - `source`;
   - `source_name`;
   - `source_domain`;
   - `rights_label`;
   - `rights_state`;
   - `reuse_permission`;
   - `public_domain_status`;
   - `image_state_code`;
   - refusal labels such as missing chronology/evidence.

3. What makes a deterministic lane usable rather than merely correct?

   Open: source/rights answers may need short plain-language wrappers, but the
   wrapper must not upgrade, reinterpret, or soften the source-provided rights
   status.

4. How should mixed lanes be measured?

   Proposed answer:

   - report deterministic assembly time;
   - report Qwen generation time if invoked;
   - report end-to-end `hybrid_system_latency`;
   - never label skipped-generation latency as `qwen_generation_latency`.

5. What is the right baseline?

   Candidate baselines:

   - all-Qwen generation over the current Round 03 prompt;
   - deterministic refusal/source-rights only;
   - mixed deterministic required fields plus Qwen explanation;
   - generative lanes with stricter evidence compression and length control.

## Evaluation Questions

1. Can a hybrid-lane pilot preserve the Round 03 contract baseline?

   Target: 0 runtime errors, 0 metric issues, 0 contract failures, 0 contract
   warnings.

2. Which latency metric should be primary?

   Candidate:

   - primary user-facing metric: `hybrid_system_latency`;
   - model-specific metric: `qwen_generation_latency`;
   - tail metric: P95 and max by lane.

3. How should usability be judged?

   Candidate dimensions:

   - helpfulness;
   - clarity;
   - source/rights transparency;
   - refusal clarity;
   - whether the answer gives enough next-step guidance;
   - whether a deterministic answer feels abrupt or under-informative.

4. How should rights-aware correctness be judged?

   Candidate:

   - exact field preservation for source/rights values;
   - no inferred permission;
   - no public-domain upgrade;
   - no omission of image-state caveat;
   - clear distinction between source metadata and legal conclusion.

5. How should refusal correctness be judged?

   Candidate:

   - refusal appears when evidence is absent;
   - no unsupported first/earliest claim;
   - no invented title/date/source;
   - answer offers a safe next step only if it remains evidence-bounded.

## Literature Questions

1. Is there prior work explicitly asking "what should not be generated" in RAG?

   Current finding: related work exists on RAG faithfulness, abstention,
   retrieval correction, guardrails, and constrained decoding, but direct
   framing around non-generation lanes appears less covered.

2. Is deterministic evidence-field delivery closer to guardrails, structured
   generation, or UI design?

   Current answer: it sits across all three. Guardrails explain why control is
   needed; structured generation explains constraints; UI/runtime design
   explains why exact fields can be rendered by the system instead of generated.

3. Can cultural-heritage rights sources support a rights-aware RAG claim?

   Current answer: yes, but carefully. RightsStatements.org and Europeana
   support the importance of machine-readable rights metadata. They do not
   provide legal validation for fixture records or generated answers.

4. Is browser-locality central or incidental?

   Current answer: central. The 0.8B browser-local setting makes generation
   expensive and capability-limited enough that deterministic/generative
   division of labor becomes a systems design question, not just a style choice.

## Risks

1. Overclaiming model performance.

   Risk: deterministic lanes could make the overall system faster, but that
   must not be described as faster Qwen generation.

2. Overclaiming legal correctness.

   Risk: exact rights-field delivery is not legal advice. The assistant can
   preserve source metadata but cannot adjudicate copyright.

3. Overfitting to current fixture lanes.

   Risk: the lane taxonomy may reflect this benchmark more than general
   archive RAG usage.

4. Making deterministic answers too terse.

   Risk: users may need context around why a refusal happened or what a rights
   field means.

5. Confusing this branch with Round 03 execution.

   Risk: this branch should inform the next main-line optimization but should
   not block it.

## Main-Line Feedback Candidates

These are safe to feed back into Round 03 planning:

1. Add a 50-query hybrid deterministic-lane pilot as a research-only variant.
2. Keep deterministic refusal and source/rights rows separate in latency
   reporting.
3. Add `hybrid_system_latency` and `qwen_generation_latency` labels.
4. For source/rights answers, consider exact field rendering before generation.
5. For refusal lanes, test deterministic refusal against generated refusal as a
   controlled comparison.
6. For generative lanes, focus on evidence compression and answer-length
   control rather than deterministic substitution.
7. Add human review prompts that distinguish correctness, usefulness, and
   perceived sufficiency.
