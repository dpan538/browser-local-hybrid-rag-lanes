# Browser-Local Hybrid RAG Lanes

Reproducible research lab for hybrid answer lanes in browser-local
small-model RAG: separating deterministic evidence-field delivery from
generative research guidance.

## Research Question

What should not be generated by a local small model in browser-local RAG?

This repository studies the division of labor between:

- deterministic UI/runtime layers for exact source, rights, provenance, image
  state, and insufficient-evidence refusal answers;
- browser-local small-model generation for explanatory, comparative, and
  research-guidance answers.

## Status

This is an independent research repository, split out from the exploratory
`browser-local-rag-lab` branch work. It is not an archive product iteration and
does not contain model weights, browser cache, or downloaded image assets.

Initial contents:

- literature memo;
- related-work matrix;
- open questions memo;
- methodology build plan.
- deterministic lane contract;
- ablation and evaluation protocol;
- review sheet guide.

## Current Framing

The working claim is that browser-local small-model RAG should not treat the
local model as the universal answer surface. Some answer lanes are
contract-bearing field delivery tasks, while others are synthesis tasks.

Candidate lane split:

- deterministic source/rights lane;
- deterministic insufficient-evidence refusal lane;
- mixed deterministic field prefill plus bounded explanation;
- generative comparison lane;
- generative research-guidance lane;
- generative current-object explanation lane.

## Latency Vocabulary

This repo keeps two metrics separate:

- `qwen_generation_latency`: time spent in local model generation.
- `hybrid_system_latency`: end-to-end user-visible answer latency after
  retrieval, deterministic rendering, contract checks, optional generation, and
  UI/runtime assembly.

If a deterministic lane skips model generation, it must not be reported as
faster Qwen generation.

It also keeps two correctness claims separate:

- deterministic lane correctness: the output follows rules over the supplied
  evidence;
- evidence correctness: the supplied evidence is semantically correct relative
  to the source.

The first can be checked mechanically. The second requires source audit.

Install fixture-validation dependencies:

```bash
pip install -r requirements.txt
```

Validate the sample fixture:

```bash
python scripts/validate_fixture.py fixtures/experiment_fixture.jsonl
```

Validate the current protocol bundle:

```bash
python scripts/validate_protocol_bundle.py
```

## Boundaries

This repository should not commit:

- model weights;
- browser cache;
- downloaded image assets;
- private archive runtime state;
- cookies, sessions, or local credentials;
- product-specific archive logic.

The goal is a clean, reproducible research artifact.
